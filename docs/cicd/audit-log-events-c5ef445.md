# Audit Log Events

Learn about the audit log events emitted by SAP Continuous Integration and Delivery and review example log messages.



## Context

SAP Continuous Integration and Delivery writes audit-relevant events to the SAP Audit Log service. These events help you track configuration changes and security‑relevant activities performed in the service.

This section describes the audit log events emitted by SAP Continuous Integration and Delivery and provides example log messages.



## How to Read Audit Log Entries

Each audit log entry generated by SAP Continuous Integration and Delivery is written as a JSON object embedded in the `message` field of the outer audit log envelope.

### Event Categories and Attribute Value Conventions

SAP Continuous Integration and Delivery uses different conventions depending on the audit category:

-   **Configuration events \(`audit.configuration`\)**

    -   Attribute values are recordet using the fields `old` and `new`.

    -   For `create` operations, only `new` is present.

    -   For `delete` operations, only `old` is present.


-   **Security events \(`audit.security-events`**\)

    -   Attribute values are recorded using a single `value` field.

    -   These events also contain a data field with a human-readable event description.





## Configuration Events \(`audit.configuration`\)

For each object type, the following sections provide an example of an update operation, which includes both `old` and `new` values. Differences for create and delete operations are described after each example.

## Security Events \(`audit.security-events`\)

Security events record security‑relevant actions and failures.



### Credential Used During Build

Logged whenever a stored credential is used during the execution of a job.

**Identification**

-   `category: "audit.security-events"`

-   `data` describes which credential was used by which job and build.

-   Attributes include: `credential-reference`, `credential-type`, `job`, `build-number`


**Possible Values for `credential-type`**

`webhookToken`, `cloudConnector`, `serviceKey`, `secretText`, `basicAuth`, `basicAuthForCustomIdP`, `certificateBasedAuthForCustomIdP`, `kubernetesConfiguration`, `containerRegistryConfiguration`

**Example**

> ### Sample Code:  
> ```
> {
>   "uuid": "e9741aa1-0738-4402-a838-3bc2e185fc59",
>   "user": "<user e-mail>",
>   "time": "2025-03-12T09:14:51.169363300Z",
>   "id": "02fc6eb2-fd3f-4833-9e73-d5f68797a2ef",
>   "data": "Credential '<credential id>' used by build number '<build number>' of job '<job id>'",
>   "attributes": [
>     { "name": "credential-reference", "value": "<credential id>" },
>     { "name": "job",                  "value": "<job id>" },
>     { "name": "credential-type",      "value": "basicAuth" },
>     { "name": "build-number",         "value": "<build number>" }
>   ],
>   "category": "audit.security-events"
> }
> 
> ```



### Authorization Failure

Logged when an authenticated user is denied access because of insufficient permissions.

**Identification**

-   `category: "audit.security-events"`

-   `data` contains `"Attempt to access cloudci-api with failed authorization: requested url: '<url>'"`

-   `ip` records the IP address of the caller


**Example**

> ### Sample Code:  
> ```
> {
>   "uuid": "081cde8b-7e96-4973-93d1-643e79b534ae",
>   "user": "<user>",
>   "time": "2025-03-12T09:22:31.524236036Z",
>   "id": "0494ca40-58e2-44dc-bb99-8dcb2e61451d",
>   "ip": "<caller ip address>",
>   "data": "Attempt to access cloudci-api with failed authorization: requested url: '<requested url>'",
>   "attributes": [],
>   "category": "audit.security-events"
> }
> ```
